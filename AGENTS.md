# Project collaboration preferences

- After each substantial change, create a descriptive Git commit and push it to the configured GitHub remote. The user explicitly authorized this standing workflow on 2026-10-25, including substantial specification and documentation changes.
- Run checks appropriate to the change before pushing. Keep generated files, local note workspaces, credentials, and build artifacts out of commits.
- Use ordinary pushes; do not force-push or overwrite remote work. If a push is blocked, report the reason and whether the commit remains local.
- During planning discussions, update the specification as appropriate and keep proposals distinct from approved decisions; do not start application implementation unless requested.
