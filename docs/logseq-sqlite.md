# Logseq SQLite: private converter and blocked personal trial

Updated November 4, 2026. The app's existing import screen supports exported Markdown/Obsidian/Logseq **file graphs**. A separate experimental developer adapter now reconstructs supported SQLite graphs, converts static content and publishes a validated private folder through a lock-owned native operation. Synthetic end-to-end imports pass. The selected personal graph is **not imported**: its preflight found missing asset files and unsupported constructs. No personal folder or access policy was changed.

## Importer-only content boundary

The user permits only importer software to read the selected export for transfer; no AI may inspect or receive its contents. `logseq_sqlite_snapshot.py` opens SQLite with `mode=ro&immutable=1`, extensions disabled, trusted schema off and query-only mode. Existing WAL/SHM/journal files and redirected sources are refused. SHA-256, byte length, modification time and sidecar presence are compared before/after. Native publication copies original source bytes without opening the source SQLite for writing.

The internal Node Transit codec sends payloads only into a captured importer pipe; stderr is discarded. Driver output contains fixed codes, counts and booleans, never schema/attribute names, titles, text, SQL messages, asset names or record values. All exceptions are sanitized. Do not open private staging bundles, add payload logging, paste records into a model prompt or substitute a personal graph for a fixture. Generated private diagnostics remain ignored locally; no graph counts or content are committed. The independent adapter uses pinned Apache-2.0 `transit-js` 0.8.874, not vendored Logseq code.

## Implemented conversion

- Reconstruct live EAVT B-trees and separator keys, verify counts, recognize integer schema aliases and replay transaction tails including exact retractions, cardinality-one replacement, cardinality-many values and redundant assertions. Tuple/dynamic-schema transactions and inconsistent state fail closed.
- Recognize the supported DB graph format/version family (65.x through public 65.35), page/class/property/journal identities, source UUIDs, parent/page ownership and fractional sibling order. Reject cycles, ambiguous/missing order, unresolved identities and unaccounted authored nodes.
- Convert headings, ordinary Markdown, native nested outlines, code, quotes, inline highlight and supported task state. Resolve UUID page/block references with native stable links outside code. Preserve visible property/class-schema values as inert local tables, including typed values and referenced entities; hidden/internal metadata stays in the exact original archive. Preserve source timestamps and page tags where supported.
- Resolve built-in background values through Logseq default-property references without evaluating CSS. Preserve block palette/hex styling in validated rich-text attributes; standard palette names use Noted’s local palette, so custom Logseq themes are not pixel-identical. Unrecognized CSS or page-title background presentation still blocks. Recycled **pages** map to native Trash with their subtree, identity, source archive and hard AI denial intact; restoring a page or its backup cannot grant AI access. Recycled individual block subtrees still need a restore-position adapter. Macro/script examples inside literal code remain inert content; live dynamic constructs are gated.
- Materialize supported local raster files from the selected copy's adjacent `assets` folder or a separate explicitly provided `--assets` folder, with immutable source checks and native image validation; preserve original asset bytes and the complete original SQLite in UUID `.source` archives. Renamed/nested files may match by exact graph-declared SHA-256 inside that folder; no title guessing or path escape is allowed. All accessed source asset hashes, byte lengths and modification times are rechecked. External URLs are not fetched. Unsupported attachments block publication rather than being mistaken for images.
- Validate the entire bundle and native notes, reconcile counts, persist hard AI denial before canonical writes, retain a recoverable publication manifest and guard, and preserve existing note files. A native desktop command uses its writer mutex; the administrative CLI requires the workspace writer lock. Existing destinations/IDs and changed bytes are never overwritten.
- Save ordinary migration provenance plus SQLite entity/block mappings. The existing **Recover original imported files** workflow and portable backup/restore preserve original database/image bytes and AI denial.

The raw reader has a 256 MiB ceiling; private publication currently also obeys the existing recovery archive's 32 MiB per-source-file limit, 5,000 pages, 50,000 authored nodes, bounded decoded structures and 20 outline levels. No data is truncated to meet a limit.

## Actual preflight and blockers

The software-only trial restored the selected snapshot and transaction groups, then stopped with `GRAPH_ASSET_FILES_REQUIRED`. Even after using the supplied asset folder and exact-checksum lookup, required local asset files remain unavailable; it also includes external assets, unsupported attachment formats and dynamic syntax outside the current converter. Additional importer-only diagnostics distinguish missing checksum-identified bytes from alternate filenames, local archives and known remote metadata without exposing source names or values. The ignored local report records only structural counters and distinguishes statically referenced assets from other records. Available source files match graph checksums, and every local file accessed for matching passes before/after integrity checks. No source payload was shown to an AI, no external asset was fetched, source integrity/sidecars were unchanged, and no real notes were published.

Before publication, obtain a complete exported copy with its assets and finish the remaining adapters or obtain an explicit local loss-review decision. Static math, live embeds/queries/custom macros, page-title backgrounds, recycled individual block subtrees and non-raster attachment behavior are not certified. PDFs require a local viewer/annotation adapter; Office files need an explicit attachment representation instead of being mistaken for renderable images. The SQLite snapshot stores asset references and checksums, which do not replace the referenced file bytes. Unsupported live code is never executed and remote media is never fetched by this workflow. This build refuses those cases rather than silently approximating the requested formatting. Even a complete asset export can still hit a format blocker. Do not inspect private schema/records to infer a mapping; develop from public documentation and synthetic fixtures.

## Developer commands and verification

`scripts/logseq_diagnostics.py` is a software-only, fixed aggregate classifier for the explicitly selected source and asset folder. It returns only known counters/booleans/codes, checks source integrity, never probes paths mentioned in records outside the selected asset root and never publishes. `scripts/test_logseq_diagnostics.py` checks output canaries and path restrictions using synthetic fixtures.

Build `noted-private-import` and the matching `noted-agent` with Cargo. `npm run test:logseq-snapshot` and `npm run test:logseq-private` exercise only synthetic sources. The latter uses the actual native CLI and both local/hosted MCP audiences, source/image archives and exact bytes, private inheritance, interrupted/resumed publication, older-client refusal and backup/source recovery. No model calls are needed to verify denial. Run `npm test` and the native desktop suite for the rest of the app.

The private driver `scripts/logseq_private_import.py` accepts explicit `--source`, `--node` and `--publisher` paths. Pass `--assets ABSOLUTE_LOCAL_ASSET_FOLDER` when the assets live separately. Default is validation only; `--publish --workspace ABSOLUTE_PATH` is the explicit publication action after safe validation. Its private bundle is temporary and never displayed. A locked active workspace returns `WORKSPACE_LOCKED`; do not force-close unsaved work or bypass the lock. The native app also exposes an internal lock-held publication command for a prepared bundle, but the ordinary SQLite import UI is not released.

Use a complete new exported copy for further trials; preserve the original. [AI exclusion behavior and compatibility guards](ai-privacy.md) remain mandatory across every publication and restored copy. Hosted connection setup remains separate and pending approval; no credentials were created.
