# Proposed migration from Obsidian and Logseq

Assessed November 3, 2026. Redley requested assessment and documentation of this idea. **No importer is implemented by this plan, and no personal vault/graph was located, read, imported or modified.** Implementation and selecting any personal source are separate next steps.

## Current capability and the first dependency

Noted currently provides Markdown *typing shortcuts*, canonical V1/V2 JSON notes, stable whole-note links, nested folders, tags, note-owned raster assets, and its own checksummed backup/restore. Component-definition JSON import is unrelated to importing a note library. There is no general Markdown parser/importer, Obsidian adapter or Logseq adapter.

`src/note-links.ts` and native `document::validate_href` accept `noted://note/<UUID>` without fragments. Nested editor blocks have IDs, but cross-note heading/block navigation is not implemented. Reliable block-reference migration needs a validated note-plus-block target, navigation/selection behavior and index/projection round-trip support first. A note-level fallback must be reported as degraded, not described as a preserved block reference.

The Note model has a fixed metadata schema, and current asset storage supports PNG/JPEG/WebP/GIF with byte/dimension/frame limits. Arbitrary properties and PDF/audio/video attachments cannot be silently pushed through those interfaces. New import-provenance/archival-blob storage must also participate in portable backup/restore before migration is called recoverable.

## Source profiles

| Profile | Proposed input | Required distinctions |
| --- | --- | --- |
| Generic Markdown | A user-selected exported folder of `.md` files and local assets | CommonMark/GFM subset, file-relative links, nesting, encoding and explicit unsupported-feature diagnostics. |
| Obsidian vault copy | Markdown files, folder tree and referenced attachments | Wikilinks and Markdown links, aliases, frontmatter, note/heading/block targets, embeds and callouts. Do not execute or ingest plugin/config code. |
| Logseq file graph copy | Exported/copied pages, journals and assets | Outlined blocks, page/block properties, stable `id::` identity, `((uuid))` references, page links, task/status markers and embeds. Do not infer journal dates from one hard-coded filename format. |
| Logseq DB export | A version-identified export chosen in Logseq | Standard Markdown export is a limited route; EDN or documented DB export needs its own adapter and fixtures. Never operate on a live database. |
| Logseq Markdown Mirror | A version-identified mirror/export | Separate profile: its page identity, property nesting and node references differ from file graphs. Do not apply the old graph parser unchanged. |

These distinctions come from primary documentation, not tested compatibility claims. [Obsidian's link guide](https://help.obsidian.md/Linking+notes+and+files/Internal+links) documents wikilinks, Markdown links and heading/block destinations. [Logseq's Markdown reference](https://github.com/logseq/docs/blob/master/pages/Markdown.md) documents file-graph references, properties, embeds and task markers. Its [DB documentation](https://github.com/logseq/docs/blob/master/db-version.md#export-and-import) describes export choices and notes that standard Markdown omits some graph data. The [Markdown Mirror syntax](https://github.com/logseq/logseq/blob/master/docs/logseq-markdown-syntax.md) explicitly concerns DB graphs and has a different identity/property representation. Obtain the actual source version/export type before promising fidelity.

## Recommended migration pipeline

1. **Choose a source copy and run a read-only inventory.** The user explicitly selects a vault/export; do not search personal directories automatically. Build a bounded manifest of paths, sizes, SHA-256 digests, dialect/version and encoding. Exclude app caches, plugins, credentials, VCS data and trash by default; list exclusions. Reject redirected paths, archive traversal and files escaping the chosen root. No remote downloads or source writes. Detect changed source bytes and request a stable copy instead of mixing revisions.
2. **Parse into a source-aware intermediate tree.** Use a maintained Markdown AST parser with explicitly enabled dialect extensions. Preserve headings, paragraph boundaries, ordered/unordered/task lists, tables, code fences, marks and inline links where Noted supports them. Source spans belong on diagnostics. Parse frontmatter/properties as inert data, with bounded nesting and no evaluation. Retain original bytes and arbitrary metadata in a batch archive; display useful unmapped properties as readable content with a report entry. HTML/scripts, macros and queries remain inert source text or clearly labelled fallbacks.
3. **Allocate identities before resolving references.** Give every destination note, folder, block and asset a stable mapping in a batch manifest. Use normalized relative paths plus source IDs, never title alone. Detect duplicate source UUIDs, duplicate aliases, Unicode/Windows case collisions, ambiguous basenames and broken targets. Resolve Markdown relative paths, percent-encoding, wikilink paths/aliases and external page IDs in a second pass. Never choose the first ambiguous title silently.
4. **Convert content and copy supported assets.** Map the physical source folder tree to new folder IDs. Keep Logseq namespaces as page identity unless the user explicitly chooses to turn them into folders. Preserve outline parent/child order and original task/status data; Noted's checked boolean alone cannot encode DOING/LATER or recurrence. Validate and copy supported raster bytes into each owning note. For other attachments, preserve bytes in the batch archive and report that inline rendering/opening needs a generic-attachment feature. Keep remote URLs as explicit links without fetching them. Missing, oversized or invalid assets are diagnostics, not empty replacements.
5. **Resolve note and block links.** Whole-note links can map to existing Noted IDs. Heading anchors, Obsidian block IDs and Logseq block UUIDs should map to validated destination block targets once supported. Preserve link labels. Transclusion/embeds should initially be a labelled snapshot plus a link to the source target, with loss reporting; Noted's current-note-only ownership rules do not provide live shared editable blocks. Dynamic queries, Dataview, plugin widgets, whiteboards, math/footnote renderers and arbitrary CSS have no fidelity promise.
6. **Preview a reconciliation and loss report.** Show source/destination counts and per-file/per-block outcomes: preserved, normalized, downgraded, archived-only, skipped or blocked. Include line/column, original syntax, reason, proposed target and unresolved/ambiguous link choices. Distinguish data already omitted by the source export from limitations of Noted's conversion. Every source note, referenced attachment and link must be accounted for; no unexplained dropped bytes. Block publication on unreadable notes, unresolved identity collisions or unapproved losses.
7. **Publish a separate migrated workspace only after acceptance.** Reuse the new-workspace staging/incomplete-marker/review pattern from backup restoration. Write and validate the full staged dataset, manifest and recovery archive, rebuild indexes, then offer **Open migrated copy**. Leave the source and current Noted workspace untouched. New imported folders start unshared with agents. If a later version supports importing into an existing shared folder, preview must disclose that its saved notes become agent-readable under that folder's policy.

## Recovery, repeats and reporting

Keep import provenance and exact source bytes in bounded, non-executable, UUID-named archive blobs with original names recorded as data. Extend the backup allowlist/format and inspection checks to preserve these records. Do not stash arbitrary source paths into an executable or asset URL. A recovered workspace must reopen imported notes/assets and retain the migration report while agent grants stay disabled.

The initial version should have no in-place merge or two-way sync. Batch identity and source checksums can detect a repeated import and offer another separate workspace. Incremental import later needs a conflict policy that preserves human changes on both sides. Rollback may remove an untouched staged workspace; once users edit imported notes, use hash-aware reconciliation/Trash rather than deleting an entire batch unconditionally.

Illustrative report columns: source path, source span, source identity, destination note/block, feature, disposition, reason, user decision. For example, an unresolved `((UUID))` must retain its literal source and a warning; linking it to an arbitrary same-named note is unacceptable. A PDF retained only in the recovery archive must say archived-only, not imported as a usable inline attachment.

## Implementation sequence and acceptance

1. Add note-plus-block targets and source identity/provenance/archive storage, including backup round-trip coverage. Decide supported non-raster attachment behavior.
2. Build a shared read-only inventory, safe Markdown AST conversion, two-pass identity/link resolver, staged workspace writer and loss-report UI. Start with synthetic/public fixtures only.
3. Deliver the generic Markdown + Obsidian adapter first. Validate folder paths, aliases/frontmatter, attachments, ambiguous names and heading/block references before claiming an Obsidian migration.
4. Deliver Logseq **file graph** mapping next, with nested blocks, UUID references, page/block properties, journal variants and task-state preservation.
5. Add versioned Logseq **DB/EDN/Mirror** adapters after obtaining representative exports and documenting their semantics. A deliberately limited Markdown route can ship earlier only with explicit completeness limits.

Fixtures must cover Unicode and duplicate filenames, escaped/percent-encoded links, case collisions, mixed newline/encoding failures, deep outlines, task states, tables/code, block references and cyclic embeds. Test missing/unsupported/oversized assets, remote links without requests, symlink/archive escapes, cancellation, interruption, unchanged-source verification and deterministic repeat detection. Verify renamed/moved/restored destination links, save/reload/Undo, note/asset hashes, no automatic agent sharing, and complete backup/restore of reports and archived originals.

Benchmark bounded memory and time on 100/1,000/10,000-file fixtures, plus actual reference hardware when available. Current correctness suites cover the existing editor/recovery/agent features; **they do not constitute importer tests**, because no importer has been built. Before any personal trial, the user should choose the source platform/version, an exported copy, desired attachment handling and acceptable fallback policy.

No dependency here prevents the delivered daily-use/agent milestone from operating. Block anchors and archival provenance are prerequisites for the proposed migration feature, not blockers on current whole-note retrieval or static-note formatting.
